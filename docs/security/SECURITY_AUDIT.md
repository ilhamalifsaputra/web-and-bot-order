# Audit keamanan Trustance ? 8 Oktober 2026

Audit bersumber dari kode repository; indikator guest cancelled/tiket berisi SVG tidak membuktikan kompromi. Tidak ada pentest produksi, panggilan provider pembayaran riil, pembacaan data pelanggan, maupun perubahan Cloudflare/VPS. File lokal pengguna `.claude/settings.local.json` tidak disentuh. Tidak ditemukan AGENTS.md pada jalur repository/parent yang dapat diperiksa; enumerasi home dibatasi sandbox.

## Arsitektur dan batas kepercayaan

- `apps/server/src/index.ts:131` menyusun Fastify admin, storefront, grammY bot, outbox dan poller dalam satu proses. Host dispatch memilih storefront bila cocok SHOP_PUBLIC_URL; sisanya admin. Mode bot polling atau `POST /tg/<secret>` dengan pemeriksaan header Telegram (baris 156). Tidak ditemukan websocket; SSE order ada pada kedua web (`apiOrderDigiflazzStream.ts`, admin `orderDigiflazzStream.ts`), setelah auth/ownership.
- Dua React SPA di `apps/storefront/client`, `apps/web-admin/client`. Prisma PostgreSQL; `prisma/schema.prisma`: User 21, WalletTransaction 94, PasswordResetToken 153, Order 645, OrderItem 845, Payment 1132, SupportTicket 1445, TicketMessage 1534, AuditLog 1613, NotificationOutbox 1641, Processed*Tx 1720?1794, IdempotencyRecord 1861, FinancialTransaction 2117, LedgerEntry 2186. Sesi menggunakan cookie bertanda HMAC + JTI di Setting, bukan tabel session web khusus. BotSession/ProcessedTelegramUpdate menangani bot.
- Guest checkout membuat user guest dan cookie HttpOnly/SameSite=Lax. Registered customer memakai password atau Telegram Login Widget HMAC-SHA256; tidak menggunakan WebApp initData. Admin memakai password/2FA dan allowlist server, bukan Telegram ID yang dikirim client saja. Cookie Secure ditentukan WEB_COOKIE_SECURE, harus benar di produksi; TTL/JTI diperiksa server.
- Checkout web `POST /api/v1/checkout`, instant topup `/api/v1/topup/order`, wallet `/api/v1/wallet/topup`; kanonik harga, item requirement, diskon, FX/snapshot dan fee dihitung service DB. Idempotency-Key dan claim invoice sudah ada untuk checkout/instant topup. Pending-order cap dan cart quantity cap sudah ada. Key idempotensi tetap opsional, bukan pengganti batas abuse.
- Alur: validasi/auth ? harga backend + reserve stock/wallet/voucher dalam transaksi ? snapshot/payment attempt ? invoice provider ? callback authenticated/live status ? ledger unik/state claim ? stock/manual/Digiflazz ? outbox web/bot/email. Digiflazz recheck mengunci claim dan tidak mengirim pembelian baru dari callback. Poller Binance/Bybit juga memakai ledger processed transaction.
- Status nyata OrderStatus: PENDING_PAYMENT, PAYMENT_DETECTED, CONFIRMING, CONFIRMED, PENDING_VERIFICATION, PAID, PROCESSING, DELIVERED, CANCELLED, REJECTED, REFUNDED, UNDERPAID, FAILED, PARTIALLY_DELIVERED. Expiry melepas hold melalui CANCELLED, bukan enum EXPIRED tersendiri. Status UI fulfillment/payment merupakan proyeksi terpisah; jangan dicampur dengan DB/provider.
- Support: customer authenticated ? validasi input/order ownership ? buffer maksimal 3 lampiran ? tulis file random ? SupportTicket/TicketMessage ? React text nodes/admin/bot. Guest tanpa sesi tidak dapat membuat tiket; sesi guest checkout normal mengikuti policy customer. Recovery guest baru hanya akses baca satu order.
- Docker app port hanya loopback; overlay PostgreSQL produksi tidak mempublikasikan port. `deploy/nginx/telegram-shop.conf` adalah contoh reverse proxy. TRUST_PROXY kosong berarti false; req.ip menggunakan rantai tepercaya Fastify. Orange-cloud DNS, firewall/origin bypass, konfigurasi proxy yang benar-benar terpasang dan jumlah replica produksi tidak dapat dibuktikan dari repo.

## Area sensitif yang telah diperiksa dan proteksi yang sudah ada

- BOLA order list/detail/status/cancel/info dan ticket list/detail/reply/close/reopen memakai customer dari cookie tervalidasi dan ownerId; detail mismatch404. SSE memeriksa ownership sebelum hijack. Admin endpoint mutasi (`orders approve/fulfill/cancel`, `users wallet/ban`, settings/admins) memakai csrfProtect dan RBAC canMutate; audit actor dilakukan service/route. Roles support dapat operasi order sesuai kebijakan repository; perubahan matriks finansial perlu keputusan bisnis, bukan diinferensikan.
- TokoPay `checkout.ts:1222`: md5 merchant:secret:ref sesuai dokumentasi; karena status/amount tidak termasuk signature, kode melakukan checkTransaction server-to-server. PayDisini :1360 menggunakan MD5 key+unique_code+CallbackStatus dan live recheck. NOWPayments :1508 HMAC SHA512 JSON terurut + linkage/amount/currency. Digiflazz :1652 HMAC SHA1 raw body + check transaksi yang pernah dispatched. Signature invalid tidak menandai paid.
- Ledger processed provider tx, Payment unique reference, conditional state transitions dan transaksi mencegah replay/double credit. `orders.ts` claimGatewaySlot/settlePaidOrder, `wallet_checkout.ts` dan suite concurrency menjadi bukti. Underpayment diarahkan manual; overpayment mengikuti kebijakan ledger yang sudah ada. Tidak mengubah toleransi nominal/kebijakan refund hanya untuk audit.
- Tidak ditemukan input ticket dirender lewat dangerouslySetInnerHTML di dua SPA. Teks SVG dalam pesan tetap teks. Lampiran image memeriksa magic bytes PNG/JPEG/WEBP; SVG tidak diizinkan. Video masih MIME/container allowance tanpa full decode, dipertahankan sebagai residual; CSP/nosniff dan private access membatasi eksekusi.
- Prisma parameterized queries dipakai; raw SQL yang ditinjau untuk support/report memakai Prisma.sql, raw unsafe integrity berisi konstanta. Tidak ada endpoint customer arbitrary-URL fetch yang ditemukan. Fetch Telegram file admin memakai domain fixed; provider API_BASE dari deployment bukan input customer. SSRF open fetch customer: tidak applicable pada jalur yang ditemukan, bukan klaim seluruh codebase bebas SSRF.
- CSRF cookie sudah token + Origin/Referer, session-mint juga Sec-Fetch-Site. Origin helper lama membandingkan hostname (bukan full scheme/port); token tetap diperlukan mutasi. Fine-tuning exact origin dicatat P2 untuk staging lintas port. Tidak ada wildcard CORS credentials yang ditemukan; API first-party same-origin.
- Logs baru requestId, resolved IP, route template, status, ms; throttled support menambah actorId/decision. Timestamp Pino milidetik. Body/email/token tidak ditambahkan; reset/tg secret path tetap redacted. Tidak ada secret produksi ditampilkan. Dependency audit dilaporkan terpisah dengan hasil aktual.

## Keterbatasan / risiko residual

Snapshot audit kode bukan bukti semua endpoint telah dipentest. Hasil rinci tes ada di SECURITY_TEST_REPORT. Production DNS/Cloudflare plan, firewall, credential permissions, traffic NAT, retained caches, race lintas multi-replica dan browser/payment staging belum diperiksa. Token recovery adalah bearer dapat direplay untuk baca satu order sampai expiry; logout merotasi sesi tetapi tidak membatalkan token stateless. Secret rotation membatalkan semua token/cookie dan memerlukan koordinasi. Link recovery lama tidak dapat dipakai; owner dengan sesi normal memperoleh link baru, selain itu bantuan admin setelah verifikasi kepemilikan. Attachment legacy URL publik mungkin pernah tercache dan perlu purge; jangan hanya deploy backend.
